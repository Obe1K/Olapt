# Проверка сборки в GitHub (без Mac и без аккаунта Apple)

Цель: убедиться, что проект компилируется в Xcode 26 и запускается в симуляторе. Виртуальный Mac предоставляет GitHub Actions.

## 1. Подготовка (один раз)
1. Зарегистрируйтесь на https://github.com (бесплатно).
2. **New repository** → имя, например, `olapt` → **Public** (бесплатные минуты) → *не* ставьте галочки «Add README», «.gitignore» → **Create repository**.
   В репозитории нет паролей и ключей, скрывать нечего. Для приватного репозитория на бесплатном тарифе даётся 2 000 минут в месяц, но macOS-минуты считаются дороже обычных.

## 2. Загрузка файлов
1. Распакуйте `OlaPT.zip`. Откройте внутреннюю папку `OlaPT`: в ней должны лежать `README.md`, `OlaPT.xcodeproj`, `OlaPT`, `Tools`, `AppStore` и скрытая папка `.github`.
2. На странице нового репозитория нажмите **uploading an existing file**.
3. Выделите **всё содержимое** внутренней папки (не саму папку) и перетащите в окно браузера. Подождите, пока загрузится ~60 файлов.
4. Внизу нажмите **Commit changes**.

**Если `.github` не загрузилась** (скрытые папки иногда не выделяются; в Windows включите «Показывать скрытые элементы»): в репозитории **Add file → Create new file**, в поле имени введите `.github/workflows/build.yml` (слэши создадут папки), вставьте туда содержимое файла `build.yml` из архива и нажмите **Commit changes**.

Вместо браузера можно использовать GitHub Desktop или git:
```
git init && git add . && git commit -m "OlaPT"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/olapt.git
git push -u origin main
```

## 3. Запуск и результат
1. Откройте вкладку **Actions**. Сборка **Build** стартует сама после загрузки (или вручную: Build → **Run workflow**). Занимает около 5–15 минут.
2. **Зелёная галочка** — проект компилируется. **Красный крестик** — откройте запуск и пролистайте вниз до блока **Ошибки и предупреждения компилятора**, скопируйте строки со словом `error:` и пришлите мне. Полный лог — в **Artifacts → build-results → build.log**.
3. В тех же **Artifacts** лежит `screenshot-launch.png` — снимок приложения, запущенного в симуляторе. Скачайте и откройте: если вместо экрана «Словарь» видна красная строка про словари, пришлите мне снимок.

## 4. Что дальше
- Исправления я присылаю файлами; вы заменяете их в репозитории (Add file → Upload files → Commit), и сборка запускается снова.
- Когда сборка зелёная и экран выглядит нормально, переходите к разделу 9 основной инструкции: аренда Mac для проверки по тест-листу, скриншотов и загрузки в App Store.

## 5. Автопрогон экранов и скриншоты (второй workflow)

В проекте есть папка `UITests` и файл `.github/workflows/ui-tests.yml`. Это автотест: на виртуальном iPhone он сам открывает приложение, ищет слова, создаёт коллекцию, проходит все 4 уровня упражнений, открывает спряжения, тренировку глаголов и настройки и делает скриншоты каждого шага.

**Запуск (вручную, каждый раз, когда нужно):**
1. Загрузите в репозиторий папку `UITests` и файл `.github/workflows/ui-tests.yml` (Add file → Upload files; для `ui-tests.yml` при проблемах со скрытой папкой — Create new file с именем `.github/workflows/ui-tests.yml`).
2. Вкладка **Actions** → слева выберите **UI tests and screenshots** → **Run workflow** → Run workflow.
3. Через 15–25 минут откройте запуск, внизу в **Artifacts** скачайте **ui-results** (zip). Внутри: `shots_named/` с PNG-скриншотами (`01_dictionary_home.png` и т. д.), файлы `steps-*.txt` со списком шагов (строки `FAILED` означают, что элемент не нашёлся) и `uitests.log`.
4. Пришлите мне zip целиком.

Тесты «мягкие»: упавший шаг не останавливает прогон, поэтому по скриншотам и журналу шагов видно, какие экраны работают.

Скриншоты снимаются на самом большом iPhone из доступных (Pro Max), то есть подходят и для карточки в App Store (6,9″), но проверьте размер 1320×2868 перед загрузкой.
